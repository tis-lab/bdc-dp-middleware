# bdc-dp-model

The GraphQL data model, plus the Java types generated from it. The SDL files are
the source of truth. The generated Java is committed, and a normal build only
compiles it. The jar contains both the classes and the SDL.

## Layout

```
pom.xml
src/
├── main/resources/graphql/model/   SDL, the source of truth
│   ├── common.graphqls             shared enums and scalars; depends on nothing
│   ├── query.graphqls              query model: `input` types; may use common
│   └── response.graphqls           response model: output `type`s; may use common
├── generated/java/                 generated from the SDL and committed; don't edit
└── test/java/                      ModelSchemaTest
```

The SDL files contain no `Query`, `Mutation` or `Subscription` root types. Those
belong in the app's API schema, which refers to model types by name.

## Build

```sh
./mvnw verify     # compile the committed sources, test, package (no codegen)
./mvnw install    # also put the jar in ~/.m2 for the app to use
```

## Changing the schema

1. Edit the `.graphqls` files.
2. Regenerate:
   ```sh
   ./mvnw -Pgenerate generate-sources
   ```
   This deletes `src/generated/java`, then regenerates it, so classes for
   removed or renamed types go away too.
3. `./mvnw verify`, then commit the schema and `src/generated/` together.

`../bin/check-model-drift.sh` regenerates the sources and fails (exit 1) if
they differ from what git has committed. Run it in CI or before you push.

Code is generated by [DGS codegen](https://netflix.github.io/dgs/generating-code-from-schema/)
through `io.github.deweyjose:graphqlcodegen-maven-plugin`:

- `org.biodatacatalyst.model.types`: one class per input, type and enum
  (builders and all-args constructors)
- `org.biodatacatalyst.model.DgsConstants`: type and field name constants
- `org.biodatacatalyst.model.Generated`: the marker annotation on every
  generated class. It has no timestamp, so regenerating unchanged schemas
  changes nothing.

The generated code has no runtime dependencies. Codegen doesn't validate the
schemas; `ModelSchemaTest` does. It merges the three files with a stub `Query`
in place of the API schema and builds the result with graphql-java.

## Using it from the app

1. Add the dependency `org.biodatacatalyst:bdc-dp-model`.
2. Make Spring for GraphQL load schema files from every jar, so the model SDL
   is merged with the app's API schema:
   ```properties
   spring.graphql.schema.locations=classpath*:graphql/**/
   ```
3. If the app also runs codegen for its API schema, map the model types to the
   existing classes (`typeMapping`) so they aren't generated twice.
